What it does

Twenty-two modules, one menu

Every module is individually selectable, risk-labelled, and shows a live [enable ] / [disable] status derived from the compliance checks, so you can see what is already in place before you touch anything.

🔒 SSH & access

Root login, password auth, MaxAuthTries, MFA via Google Authenticator, GRUB password protection.

🔥 Network

nftables/UFW firewall, Fail2Ban, sysctl network hardening, unused protocol blacklisting, remote syslog.

📋 Auditing

auditd rule sets, AIDE file integrity, rkhunter rootkit scanning, etckeeper change tracking.

⚙️ Kernel & filesystem

ASLR, hardlink/symlink protection, SUID/SGID reduction with per-binary backup, UMASK 027 defaults.

🛡️ Mandatory access control

AppArmor profile enforcement on Debian family, SELinux enforcing mode on RHEL family.

🐳 Workloads

Docker daemon hardening, ModSecurity WAF, USB storage blocking, compiler access restriction.

Why you can run this as root

Built to be undone

This script rewrites SSH config, firewall rules and file permissions on your machine. That is a lot of trust to ask for, so every destructive action has a way back.

👁️ Preview before you commit

--dry-run prints every change the script would make and modifies nothing. Run it first, every time.

💾 Automatic backups

Modified files are copied to a timestamped /root/hardening_backup_* directory before any edit, including original SUID/SGID permission modes.

↩️ Full revert

--revert restores from backup; --revert-suid rolls back only permission changes. Revert auto-finds the most recent backup.

🧬 PAM-safe by design

Password policy is written to /etc/security/pwquality.conf — never by hand-editing /etc/pam.d/*. It also skips when multiple display-manager PAM profiles are detected.

📡 No telemetry, no network calls

Nothing phones home. The only outbound request is the optional, explicitly-invoked update check against the GitHub API.

🔍 Readable and reviewed

Plain Bash, MIT licensed, ShellCheck-clean in CI on every push, tested across Debian, RHEL, Arch and SUSE families.

The PAM-safety guarantee exists because it once went wrong. An earlier version edited /etc/pam.d/common-password directly. On a Mint box running KDE Plasma, a later pam-auth-update run reconciled around that untracked edit and broke the SDDM login. The fix — never hand-edit machine-managed PAM files — is why the current release does it the way it does.
Standards

Aligned, mapped, and independently assessable

Being precise here matters more than sounding impressive, so here is exactly what each claim means.

📊 CIS-aligned

Built-in checks follow CIS Benchmark guidance for Linux. This is alignment, not a CIS certification, and the built-in scorer is not an accredited assessment.

🎯 OpenSCAP scanning Enterprise

Runs oscap against the official SCAP Security Guide, so you get a real, assessable result under a CIS or DISA STIG profile — not our interpretation of one.

🗺️ NIST 800-53 crosswalk Enterprise

Maps each hardening module to the NIST SP 800-53 Rev. 5 controls it contributes to, for audit evidence and control-narrative work.

What this is not. The crosswalk explains which controls a module contributes to; it is not an assessment result and not a certification. For an auditable CIS or STIG score, use the OpenSCAP scan against official SCAP content — that is what assessors recognise.

FAQ

Will this break my server?

It can — any real hardening tool can, which is why the safety design matters. Run --dry-run first to see every change, keep the automatic backups, and use --revert if something misbehaves. High-risk modules (SUID stripping, GRUB password) are labelled and require explicit confirmation rather than running as part of the safe defaults.

Does it work over SSH without locking me out?

SSH hardening disables root login and password authentication. If you connect as root with a password and no key, you will lock yourself out. Set up key-based access for a non-root sudo user first, and preview with --dry-run before applying.

Is this CIS certified?

No, and anything claiming otherwise deserves scrutiny. The built-in checks are CIS-aligned. For an assessable, auditor-recognised CIS or DISA STIG result, the Enterprise tier runs OpenSCAP against the official SCAP Security Guide content.

What distributions are supported?

Debian and Ubuntu, RHEL/CentOS/Fedora/Rocky/AlmaLinux, Arch and Manjaro, and openSUSE/SLES. The script detects your distro or lets you select it, and adapts package manager and service names accordingly.

Does it send any data anywhere?

No. There is no telemetry, analytics or licence phone-home. The only outbound request is the optional update check you invoke yourself from the menu, which queries the public GitHub API. Everything else is local, and the source is there to verify that.

How does Enterprise host counting work?

A host is any machine you scan, harden or track in the dashboard. The base tier covers 10 hosts, additional hosts are $3/month each, and the flat $149/month plan covers up to 50. Above that, get in touch and we will size it.

Can I try Pro or Enterprise before buying?

Yes — get in touch and we will set up a trial. The free tier is also a genuine product rather than a crippled demo, so you can validate the hardening itself before paying for the automation layer.
